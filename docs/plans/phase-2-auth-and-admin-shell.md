**Decisions / findings**

  verify here, and hashes written here verify in the old backend (needed during the overlap). The test
  fixture `legacy-password.fixture.json` was generated by the legacy code for a test-only password.

  `requireAdminPage()`** and every action calls `requireAdmin()`; `src/proxy.ts` only does an optimistic

  instead of fetching the session for every visitor.
- Rate limit: Upstash when configured, otherwise a **per-instance in-memory** limiter (zive failed fully
  open). 5 attempts / 15 min per IP and per email.
- Test-only admin `test-admin@example.test` exists in the test DB (password = `TEST_ADMIN_PASSWORD` in
  `.env.local`). `scripts/create-admin.ts` prompts without echo.
- Upgraded to **Next 16.4.0** (bundles `dist/docs` again). The styleguide moved to `/styleguide` (dev-only).

**Not done:** the real admins' own passwords weren't tried (unknown to us). Compatibility is proven via the

## ⚠️ Key gotchas
1. **The format is `hash.salt` in one `password` field,** not zive's separate `hash`/`salt`. Split
   on the **first** `.` (hex never contains dots). Salt = the hex **string**, not decoded bytes.
2. **`password` is `select:false`.** Only `findByEmailWithPassword` selects it, and it's never in a DTO.
3. **Guards live in every action and the presign route,** not just in the layout. Server actions are
   public HTTP endpoints.
4. **Email lookup:** legacy stored emails as typed. Normalise to lowercase+trim for the **query**
   using a case-insensitive collation/regex-escaped match, but don't rewrite stored values.
5. **Auth.js v5 beta:** read its current docs for the `authorize` error API (`CredentialsSignin`
   subclass) and the Next 16 integration. Zive's file is a working reference for beta.31; verify on
   beta.32.
6. **Keep new hashes in the legacy format** until cutover (the legacy backend must still verify them).
